## 本版本保留的回审问题与恢复边界

本次发布没有实施以下两项 P2：

- resource 类型排除边界：strict 可接受 `Azure OpenAI resource group` 前缀；redacted 在分号等条件下可能越过 A 中的 resource group/quota，匹配到 B 中的 resource。回审用真实 SDK/loopback 已复现，作为后续匹配器修复事项保留。
- status 跳过原因：通常的关闭插件或同 turn 多 provider hook 会先清空 snapshot，随后被报告成 `no-snapshot`，遮蔽 `disabled` / `multi-request`。保守停止行为仍在，诊断精度待改进。

另有已调查、尚未采用的策略调整：

- 同一次长操作中，中途模型工具响应成功不会刷新一次身份修复额度。
- MC 历史推理预算可省略 thinkingSignature；带原始 function_call item ID 的重放可能触发 required-reasoning 400。该错误独立于跨资源文本，0.2.0 不把它纳入自动身份恢复。

当前行为声明仍见 [行为与接口](../state/behavior.md)，功能形成记录见 [脱敏 resource 错误的自动恢复](2026-11-03-redacted-resource-recovery.md)。回审与后续策略材料由 `docs/.temp/active-plan.md` 指向。

## 运行中会话应用

磁盘安装更新后，在目标 Pi 会话执行：

```text
/reload
/azure-compat status
```

status 应包含 `Last error` 字段，表明带诊断的实现已加载；在符合自动恢复防护条件的脱敏强指纹错误后，可以核对 `(redacted)` warning 与 `redacted (prepared)`。status 的 recoveries 表示准备次数，不代表服务端成功次数。
